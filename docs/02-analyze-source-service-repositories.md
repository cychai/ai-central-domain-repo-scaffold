# 分析源服务仓

## 本节目标

从本地证据识别仓库身份、职责、入口和验证方式。

## 前置输入

准备至少两个服务仓或教学仓，并确保只做只读探索。

## 为什么要做

服务名或调用关系不能单独证明职责；可靠清单需要代码、README、Agent 指南、测试和 Owner 结论交叉验证。

## 操作步骤

依次检查 Git 根、默认分支、README、AGENTS.md、目录、测试入口；把结论标成 confirmed、inferred 或 manual_required。

## 关键文件解析

服务清单字段把人类判断转换成生成器可验证的输入合同。

## 设计取舍

先收集证据再决定 read-write/read-only；候选服务不因出现在文档中就自动变为修改目标。

## 验证命令与预期结果

运行 `python3 -m central_repo_scaffold validate --config examples/domain.yaml`；预期配置通过，但业务职责仍需人工确认。

## 常见错误及根因

把 PSM 当仓库、把 APM 调用当修改授权，根因都是把定位线索误当权威边界。

## 学员练习

为每个服务写证据、Owner、验证命令和剩余未知项。

## 完成标准

每个服务都有可追溯身份和访问级别，没有猜测性的可写目标。
