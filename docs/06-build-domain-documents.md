# 构建领域治理文档

## 本节目标

建立治理、编码、质量、稳定性和安全基线。

## 前置输入

已有 Agent 文档层级和领域边界。

## 为什么要做

没有治理契约时，Agent 会把可读取误解为可修改，把声明命令误解为已验证。

## 操作步骤

分别编写 CONSTITUTION、CODING、QUALITY、RELIABILITY、SECURITY；为每份文档限定主题。

## 关键文件解析

治理文档是跨需求稳定规则，需求特定判断进入 specs 或 build-record。

## 设计取舍

文档保持短小可执行，不复制公司制度全文；只保留本领域适用约束和入口。

## 验证命令与预期结果

检查 `/tmp/rendered-central` 的结构；Git 初始化前使用脚手架 `verify`，不要提前运行生成仓 require-git 门禁。

## 常见错误及根因

把一次事故细节写成永久架构事实会过时；根因是混淆动态证据与稳定规则。

## 学员练习

把一条运行事故拆成动态证据、稳定根因和可复用规则。

## 完成标准

五类文档互不重复，并能回答允许做什么、如何证明和何时停止。
